# Оформление GitHub / Универсальная инструкция

Этот документ нужен как универсальная пошаговая инструкция: с чего начать и как пройти оформление GitHub от пустого аккаунта или репозитория до понятной публичной витрины.

Здесь нет привязки к конкретному проекту. Просто берите эту схему и подставляйте свои данные.

## 1. Сначала оформляем профиль

Профиль на GitHub нужен для первого впечатления. До того как человек откроет репозиторий, он часто смотрит именно на профиль пользователя или организации.

Что заполняем:

- имя;
- короткое описание;
- avatar или logo;
- location;
- website;
- публичные ссылки;
- pinned repositories.

Что должно получиться:

- сразу понятно, кто вы;
- сразу понятно, чем вы занимаетесь;
- есть ссылка на основной репозиторий или сайт;
- есть 3-6 закрепленных элементов, которые показывают главное.

Рекомендуемый порядок:

1. Поставить читаемый avatar или logo.
2. Заполнить имя и короткое описание одной ясной фразой.
3. Добавить сайт и 2-3 публичные ссылки.
4. Закрепить основные репозитории.
5. При необходимости создать README профиля.

Готовые заготовки под оба сценария:

- личный профиль: [github-profile-personal.md](github-profile-personal.md)
- GitHub Organization: [github-organization-profile.md](github-organization-profile.md)

## 2. Затем оформляем главный репозиторий

Главный репозиторий - это центр проекта. Он должен отвечать на четыре вопроса:

- что это;
- зачем это нужно;
- что уже есть;
- куда человеку идти дальше.

Что заполняем:

- описание репозитория;
- website URL;
- topics;
- обложка репозитория;
- README;
- Issues;
- Discussions.

Что должно получиться:

- человек за 10-15 секунд понимает смысл репозитория;
- видит, что проект живой;
- понимает, как присоединиться.

Минимум в README:

- краткое описание проекта;
- миссия или цель;
- текущее состояние;
- ссылки на важные разделы;
- способы участия;
- контакты или точка входа.

## 3. Потом настраиваем вход для людей

GitHub должен быть не просто витриной, а удобной точкой входа.

Поэтому настраиваем:

- шаблоны обращений;
- шаблон pull request;
- contact links;
- руководство по участию;
- категории discussions.

Что это дает:

- человек не теряется;
- вопросы, идеи и предложения попадают в правильные каналы;
- участие становится проще и понятнее.

Что стоит предусмотреть:

- форма для общей идеи;
- форма для предложения сотрудничества;
- форма для данных, материалов или ссылок;
- форма для технической задачи;
- ссылка на discussion, сайт или email через `contact_links`.

## 4. Затем настраиваем партнерскую коммуникацию

Если у вас есть партнеры, у которых свои аккаунты и репозитории, GitHub должен помогать координироваться публично.

Что нужно настроить:

- понятный профиль с описанием, как поддержать проект;
- pinned repositories, которые показывают основные направления;
- Discussions для идей, анонсов и координации;
- понятные шаблоны партнерских обращений;
- README с блоком для партнеров.

Что партнеру должно быть легко сделать:

- подписаться на репозиторий;
- поставить star;
- открыть issue;
- открыть discussion;
- прислать pull request;
- сослаться на проект у себя в README или профиле;
- участвовать в совместных анонсах и публикациях.

Если используется GitHub Organization, дополнительно полезно:

- оформить organization profile README;
- закрепить public pinned repositories;
- при необходимости включить organization discussions.

## 5. В конце доводим витрину до рабочего состояния

После заполнения профиля и репозитория нужно проверить, что все выглядит как единая система.

Проверяем:

- понятен ли проект новому человеку;
- есть ли один главный репозиторий;
- видны ли способы участия;
- есть ли рабочие ссылки;
- выглядят ли pinned repositories осмысленно;
- включены ли Issues и Discussions;
- есть ли 5-10 стартовых задач;
- есть ли обложка репозитория;
- не осталось ли пустых заглушек и случайных черновиков.

Для быстрого старта с уже оформленными задачами используйте: [github-first-issues.md](github-first-issues.md)

Финальный результат должен быть таким:

- профиль выглядит как оформленная точка входа;
- репозиторий выглядит как живая рабочая витрина;
- партнеры и участники понимают, куда идти и что делать;
- коммуникация не разваливается по разным каналам.

## Краткая схема из 5 шагов

1. Оформить профиль: имя, краткое описание, avatar, ссылки, pinned repositories.
2. Оформить главный репозиторий: описание, topics, README, обложка репозитория.
3. Настроить вход для людей: Issues, шаблоны обращений, PR template, contact links, Discussions.
4. Настроить партнерский слой: блок для партнеров в README, discussions, формы для сотрудничества.
5. Проверить целостность витрины: ссылки, первые задачи, публичные каналы, единый вид.
