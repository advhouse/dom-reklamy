# Контур внешней интеграции

Этот документ задает рабочую логику внешнего взаимодействия `Дом рекламы`.

Задача не в том, чтобы писать всем подряд, а в том, чтобы по каждому из пяти столпов:

- находить сильные организации и платформы;
- подписываться и наблюдать там, где это возможно;
- писать аккуратные письма;
- получать обратную связь;
- фиксировать статус контакта;
- переводить это в живой внешний контур проекта.

## Пять столпов

1. `Медиа`
2. `PR`
3. `Реклама`
4. `Дизайн`
5. `Диджитал`

## Что делаем по каждому столпу

### 1. Наблюдение

- ищем сильные компании и институции;
- ищем GitHub-аккаунты и репозитории;
- ищем фестивали, журналы, платформы, форумы и продуктовые среды;
- смотрим, где есть реальный публичный след.

### 2. Контакт

- определяем рабочий контактный путь;
- готовим письмо;
- пишем коротко и без давления;
- не обещаем того, что не подтверждено.

### 3. Обратная связь

- фиксируем ответ;
- отмечаем интерес, паузу, отказ или переадресацию;
- если есть фактический контакт, переносим его в контактный pipeline.

### 4. Интеграция

- добавляем организацию в внешнюю карту;
- связываем с нужным столпом;
- при необходимости готовим заметку, shortlist или company note;
- используем это в рейтинговом и editorial-контуре.

## Практическое ограничение

Реальные подписки на GitHub зависят от прав токена.

Реальные письма зависят от наличия:

- адреса;
- контактного лица;
- допустимого канала;
- приоритета по одному из пяти столпов.

То есть логика уже может работать, но массовое внешнее действие должно идти через нормальный pipeline, а не вручную из головы.
