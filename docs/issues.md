# Предлагаемые GitHub Issues

## 1. Утвердить назначение и формат репозитория

Описание: определить, будет ли репозиторий организационной базой знаний, сайтом, приложением или смешанным проектом.

Метки: `documentation`, `infrastructure`

Приоритет: высокий

Критерии готовности:

- выбран основной формат проекта;
- обновлены README и `docs/overview.md`;
- зафиксировано решение в `docs/decisions.md`.

## 2. Выбрать лицензию и правила использования материалов

Описание: определить лицензию для кода и отдельные правила для текстов, логотипов, фотографий и бренд-материалов.

Метки: `documentation`, `infrastructure`

Приоритет: высокий

Критерии готовности:

- выбран тип лицензии;
- добавлен `LICENSE`, если материалы открываются для использования;
- правила использования бренда отражены в `docs/brand.md`.

## 3. Добавить публичные контакты фонда

Описание: указать официальный email, сайт или страницу проекта, а также ответственных за технические и контентные вопросы.

Метки: `documentation`, `good first issue`

Приоритет: высокий

Критерии готовности:

- README содержит актуальные контакты;
- контакты подтверждены владельцем проекта.

## 4. Подготовить стартовый контент

Описание: собрать базовые тексты о миссии, деятельности, направлениях работы, команде и партнерстве.

Метки: `documentation`, `enhancement`

Приоритет: средний

Критерии готовности:

- тексты добавлены в `content/`;
- материалы вычитаны;
- спорные формулировки отмечены для согласования.

## 5. Выбрать технический стек будущего сайта или приложения

Описание: сравнить варианты стека и выбрать подходящий способ реализации публичного сайта или приложения.

Метки: `infrastructure`, `enhancement`

Приоритет: средний

Критерии готовности:

- выбран стек;
- зафиксировано решение в `docs/decisions.md`;
- обновлены `docs/setup.md` и `.gitignore`.

## 6. Создать минимальную главную страницу

Описание: после выбора стека подготовить первую версию главной страницы с понятным описанием проекта и контактами.

Метки: `enhancement`, `design`

Приоритет: средний

Критерии готовности:

- страница запускается локально;
- контент согласован;
- базовая адаптивность проверена.

## 7. Настроить базовые проверки качества

Описание: добавить форматирование, линтер и минимальные тесты после появления кода.

Метки: `infrastructure`, `enhancement`

Приоритет: средний

Критерии готовности:

- есть команды проверки;
- команды описаны в README и `docs/setup.md`;
- проверки проходят локально.

## 8. Настроить GitHub Actions

Описание: добавить CI для Pull Request после выбора стека и появления команд проверки.

Метки: `infrastructure`

Приоритет: средний

Критерии готовности:

- процесс запускается на Pull Request;
- CI проверяет форматирование, линтинг, тесты или сборку;
- секреты хранятся в GitHub Secrets, если они нужны.

## 9. Проверить доступность и мобильную версию

Описание: провести базовую проверку доступности, контраста, навигации и адаптивности будущего сайта.

Метки: `design`, `enhancement`

Приоритет: низкий

Критерии готовности:

- основные страницы корректно отображаются на мобильных и desktop-экранах;
- интерактивные элементы доступны с клавиатуры;
- найденные проблемы заведены отдельными Issues.

## 10. Подготовить onboarding для новых участников

Описание: добавить короткую инструкцию для новых участников и подрядчиков: где что лежит, как брать задачи, как задавать вопросы.

Метки: `documentation`, `good first issue`

Приоритет: низкий

Критерии готовности:

- инструкция добавлена в документацию;
- ссылка на нее есть в README или `CONTRIBUTING.md`.
