# Правила участия

## Общие принципы

- Делайте изменения небольшими и понятными.
- Описывайте причину изменения в Issue или Pull Request.
- Не добавляйте персональные данные, закрытые документы, пароли, токены и приватные ссылки.
- Сохраняйте русскоязычную документацию для материалов, ориентированных на команду и партнеров фонда.
- Используйте английские имена для технических файлов и папок.

## Рабочий процесс

1. Найдите или создайте Issue.
2. Создайте отдельную ветку.
3. Внесите изменения.
4. Проверьте документацию и доступные команды проверки.
5. Создайте Pull Request.
6. Ответьте на замечания ревью.

## Именование веток

Рекомендуемый формат:

```text
docs/update-readme
feature/site-homepage
fix/contact-form-validation
infra/add-ci
```

## Коммиты

Пишите короткие осмысленные сообщения:

```text
docs: add project roadmap
infra: add issue forms
feature: add homepage draft
```

## Контент и бренд

- Не публикуйте логотипы, фотографии, тексты и юридические формулировки без подтверждения прав на использование.
- Значимые изменения тона коммуникации, названия, визуального стиля и публичных обещаний должны проходить ревью владельца проекта.

## Проверки

Перед Pull Request выполните доступные проверки. Если проверок пока нет, укажите это в описании Pull Request.
